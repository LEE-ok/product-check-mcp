# product-check-mcp

상품 등록 검수를 SQL 규칙으로 자동화하고, Claude가 MCP로 직접 돌려보게 만든 작은 데모입니다.

## 왜 만들었나

PB 상품이 늘면 등록 단계의 검수(필수 정보, 인증 번호, 바코드, 가격, 표현)를 사람이 한 건씩 보는 방식은 물량을 못 따라갑니다. 그렇다고 전부 자동으로 넘기면 틀린 상품이 그대로 올라갑니다. 그래서 검수를 세 갈래로 나눴습니다.

| 판정 | 기준 | 처리 |
|---|---|---|
| 자동 통과 | 어떤 규칙에도 안 걸림 | 바로 등록 |
| 사람 확인 | 판단이 필요한 의심 건(가격 이상, 과장 표현, 미등록 카테고리) | 사유와 함께 담당자에게 |
| 반려 | 명확한 규칙 위반(필수 항목 누락, KC 인증 누락, 바코드 중복) | 협력사에 보완 요청 |

규칙이 틀리지 않았는지 먼저 확인할 수 있도록, 문제를 일부러 심어둔 샘플 데이터와 테스트를 같이 두었습니다.

## 결과 (샘플 20건)

- 자동 통과 11건, 사람 확인 3건, 반려 6건 → 사람이 봐야 하는 건 20건 중 3건
- 심어둔 문제 8종(바코드 중복은 상품 2개)을 모두 잡았고, 정상 상품은 하나도 걸리지 않음 (`test_checker.py`로 확인)

## 구성

```
checker.py       CSV → SQLite 적재, SQL 검수 규칙 6개, 읽기 전용 조회
server.py        위 기능을 MCP 도구 4개로 노출 (load_products, run_checks, list_rules, query)
data/products.csv 샘플 상품 20건 (가상 데이터)
test_checker.py  판정 결과·사유·읽기 전용 보장 테스트
.mcp.json        Claude Code에서 바로 서버를 붙이는 설정
```

규칙은 `checker.py`의 `RULES`에 이름, 판정, SQL을 한 줄씩 두었습니다. 규칙을 추가하려면 SQL 하나만 넣으면 됩니다.

## 안전장치

- `query` 도구는 DB를 읽기 전용(`mode=ro`)으로 엽니다. SELECT로 시작하는 문장에 쓰기를 섞어도 DB 단계에서 막힙니다.
- `load_products`는 `data/` 폴더 안의 `.csv`만 읽습니다. `../` 같은 경로는 거절합니다.
- 거절 사유는 Claude가 읽을 수 있게 오류 메시지로 돌려줍니다.

## 실행

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m pytest -q
```

Claude Code에서 이 폴더를 열면 `.mcp.json`으로 `product-check` 서버가 붙습니다. 이렇게 요청해 볼 수 있습니다.

> 상품 CSV 올리고 검수 돌려줘. 반려 건은 협력사에 보낼 보완 요청 문구로 정리해 줘.

> 카테고리별 평균 가격을 SQL로 뽑아줘.

## 한계

- 가격 이상은 카테고리 평균의 1/5 미만, 5배 초과로 단순하게 잡았습니다. 실제로는 카테고리 안에서도 용량·구성이 달라 단위 가격 기준이 필요합니다.
- KC 인증은 번호가 있는지만 봅니다. 실제 번호가 유효한지는 인증 조회 API와 연동해야 합니다.
- 샘플은 가상 데이터 20건입니다.
